# 1차 프로젝트 · AI 헬피챗 로그인 UI 자동화

- 기간: 2026.07.08 – 07.27 · 4명 팀(Team Error404) · 담당: 로그인·세션 영역
- 도구: Python, Selenium, pytest (Page Object 구조)
- 결과: 로그인 TC 59건 설계·수행(58건 통과), 그중 29건 자동화

## 파일과 작성 비중

| 파일 | 내용 | 작성 |
|---|---|---|
| `tests/test_login_pj.py` | 로그인 자동화 29건 (테스트 함수 19개, parametrize 포함) | 본인 (팀원 수정 없음) |
| `pages/login_ui_page.py` | 로그인 상세 검증용 Page Object `LoginUiPage`, 화면 문구 상수, `login()` | 팀 파일 `src/pages/login_page.py` 중 본인 부분 발췌. 팀원이 줄바꿈만 정리한 7줄 포함 |
| `pages/main_page.py` | 로그인 후 화면 Page Object (로그인 판정, 로그아웃) | 본인 |

팀 공용 `conftest.py`(본인이 추가한 `shared_driver`·`credentials` 픽스처 포함)와 설정 파일은 팀 공동 파일이라 넣지 않았습니다. import 경로는 팀 저장소 구조(`src.*`) 그대로라 이 폴더만으로는 실행되지 않습니다.

## 볼 만한 곳

- **과도기 문구 거짓 통과 제거** — `LoginUiPage.settled_error_text()`
  - 오류 문구가 1.5초 동안 바뀌지 않을 때까지 기다린 뒤 그 값을 돌려줍니다.
  - 클라이언트 검증 문구가 약 0.5초 떴다가 서버 응답 문구로 바뀌는데, 나타나는 순간 판정하면 과도기 문구를 잡게 됩니다.
  - **한계:** 시간만 보는 방식이라, 서버 응답이 1.5초보다 늦으면 과도기 문구가 확정될 수 있습니다. 2차 UI 자동화에서는 목록·일정 판정을 시간 대신 응답 도착을 기준으로 했습니다.
- **로그인 상태 거짓 통과 제거** — `MainPage.wait_logged_in()`
  - 아이디가 저장된 로그인 페이지에도 같은 프로필 아이콘이 뜹니다.
  - 그래서 아이콘과 함께 현재 주소가 앱 도메인인지도 확인합니다.
- **경계값** — `test_login_server_validation`의 TID 12
  - 명세의 이메일 256자 제한을 257자로 검증합니다.
  - 이 케이스는 결함 동작(입력 안내 대신 서버 오류 문구 노출)을 재현해 확인하도록 서버 오류 문구를 기대값으로 두었습니다. TC 문서에는 결과를 Fail로 기록하고 결함(SCRUM-31)으로 보고했습니다.
  - 결함이 고쳐지면 이 테스트는 실패합니다. 2차에서는 반대로, 결함이 있는 동안 실패하고 고쳐지면 통과하도록 결함 TC를 작성했습니다.
- **판정 위치**
  - 문구와 상태를 읽는 메서드는 값만 돌려주고, 통과·실패 판정은 주로 테스트의 `assert`에서 합니다.
  - 로그인 완료 대기처럼 Page Object 안에서 기다리며 확인하는 곳도 있습니다.
