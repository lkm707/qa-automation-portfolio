**api-part3 작성 비중**
- **컬렉션:** 원본 52 TC 중 약 95%를 제가 썼습니다. 나머지는 팀원들의 수정입니다.
  - 팀원 한 명이 TC와 단정 이름을 정리했습니다.
  - 팀장이 TC-CO-06-01, TC-CH-14-05의 요청과 단정을 바꿨습니다.
- **공개본:** 결함 재현 TC 3개와 그 준비·정리 요청을 뺀 49 TC입니다.
- **스크립트:** `run-all.sh`는 약 94%(팀원 수정 5줄), `scrub.js`는 전부 본인이 썼습니다.

## 결과 요약

- **API:** 팀 전체 자동화 TC 164건 중 152건 통과(92.7%)
  - 원본 컬렉션에서는 권한 결함 2건을 확인하는 TC 3개를 일부러 실패로 남겨, 고쳐지면 통과로 바뀌는 회귀 가드로 썼습니다.
- **부하:** 5, 10, 20, 30명 인원 4단계 모두 에러 0%, 평균 Latency 230~249ms
  - 설정 30명 중 실제 최대 동시 활성은 27명이었고, 이 범위에서는 임계 인원을 특정하지 못했습니다.
- **UI E2E:** 10건 모두 재시도 없이 통과, 기능 결함 없음
- **보고한 결함:**
  - 권한 결함 3건
  - 부하 뒤 상태 불일치 1건: 다음 날 해소됐고 원인은 확인하지 못했습니다.
  - 재현 절차는 대상 서비스의 조치 여부를 확인하지 못해 공개하지 않습니다.

## 공유 dev 서버를 지키려고 넣은 장치

- **API 자동화:** 요청 간격을 두고 한 번에 한 건씩 순차 실행하고, 재시도하지 않습니다. 5xx가 나오면 남은 컬렉션을 멈춥니다(`run-all.sh`).
- **부하 테스트:**
  - 최대 30명, 램프업 90초, 반복 3회, 요청 간 3~5초 대기로 제한했습니다.
  - 5xx 1건 또는 60초 응답 1건이면 전체를 중단합니다(`exam_cycle.jmx`).
- **비밀정보:**
  - 계정은 Git에서 제외한 `.env`와 계정 CSV로만 읽습니다.
  - 로컬 리포트에 남는 비밀번호·토큰은 치환합니다(`scrub.js`).

## 공개용으로 바꾼 것

- 서버 주소는 `*.example.invalid`, 클래스 ID는 `00000000-…`, 예시 계정은 `example.com`으로 바꿨습니다. 계정 CSV는 예시 파일만 넣었습니다.
- 운영 서버를 대상으로 한 Spike 부하 계획 초안은 공개본에서 뺐습니다.
- 조직명과 과목·차시 번호 같은 dev 환경 값 일부는 그대로 두었습니다.
