# UI E2E 시나리오

## 방식
Playwright Test 스크립트(이 저장소의 `ui-e2e/`, 원본 `part3_ui_automation/`)가 실제 브라우저를 조작해 사용자 흐름을 검증하고 시나리오별로 영상을 남긴다.
E2E는 사용자 워크플로가 중심이다. 시나리오 하나는 한 사용자 목표를 로그인부터 끝까지 이룬다.
영상·스크린샷·HTML 리포트는 재생성 산출물로 Git에서 제외한다.

## 대상 환경
- 프런트: `web.example.invalid` (미로그인 시 `accounts` 로그인 페이지로 이동, 시험은 `testroom` 시험 화면으로 이동 후 복귀)
- 조직 academy / 클래스 3팀 전용 클래스 / 과목 SANDBOX(731) / 시험 차시 01 TEST(1585)
- 계정: `project2-lxp-testflow/.env`의 학습자·교육자 계정(위 클래스에 각 역할로 가입, 학습자는 SANDBOX 수강)
- **전제: 01 TEST의 교육자 설정 "테스트 셀프 재응시 허용"이 켜져 있다.** (교육자 → 과목 → 수업 목록 → 01 TEST → 공개 설정 "수정하기")

## 공통 원칙
- 테스트 대상 기능의 조작과 결과 확인은 UI로 수행한다.
- API는 쓰지 않는다. 시험 상태 초기화는 화면의 "테스트 재응시" 버튼으로, 실패로 남은 게시글·일정 정리는 새 세션에서 UI로 한다(성공한 테스트는 스스로 지운다). 정리 실패도 테스트 실패로 보고한다. UI가 보낸 조회·저장 요청은 관찰만 하며(재호출 없음), 실패 후 정리와 UI-TC-07 미노출 확인에서는 조회가 4xx/5xx면 '없음'으로 판정하지 않는다(UI-TC-05 삭제 확인은 검색 결과 문구와 행 0건으로 판정).
- 저장 확인은 새로고침 또는 다른 역할로 재진입해 검증한다.
- 모든 테스트 데이터는 실행 시각과 프로세스 ID가 붙은 고유한 제목·일정명을 사용한다.
- 고정 대기 대신 URL, 버튼 상태, 화면 요소를 기준으로 대기한다. 예외는 게시글 저장 전 500ms 정착 대기 하나다(README 구현 메모).
- 각 테스트는 빈 세션에서 실제 로그인부터 시작한다. 2번 로그인 실패는 케이스마다 독립 세션이다.
- 같은 PC에서의 시험 시나리오 중복 실행은 파일 잠금으로 차단한다(다른 머신과는 담당자 1명 실행 규칙).
- 계정 내부 id를 쓰지 않으므로 `.env`의 계정만 바꾸면 다른 학습자·교육자 계정으로도 그대로 실행된다.

## 화면 구조
- 상단 헤더: 왼쪽 로고·LXP 드롭다운 / 오른쪽 검색·채팅·프로필 아바타(맨 오른쪽). 아바타 → 드롭다운 맨 아래 로그아웃.
- 왼쪽 사이드바: 클래스 메뉴 4개 — 클래스 홈 / 학습 과목 / 수업 일정 / 게시판. (교육자는 구성원·설정이 추가됨)
- 본문: 사이드바 오른쪽. 클래스 홈은 인사말 + 학습 과목·수업 일정·게시판 위젯.

### 1. 학습자 정상 로그인 (UI-TC-01)
| # | 조작 | 기대 |
|---|---|---|
| 1-1 | 클래스 홈 주소 진입 | 로그인 화면(이메일·비밀번호 칸, 로그인 버튼) |
| 1-2 | 아이디·비밀번호 입력 → 로그인 | 클래스 홈 URL, "안녕하세요, …님" |
| 1-3 | 왼쪽 클래스 메뉴 | 클래스 홈·학습 과목·수업 일정·게시판 4개 각각 표시, 구성원·설정·관리·편집 링크 없음 |
| 1-4 | 프로필 아바타 → 로그아웃 | 로그인 화면으로 이동 |
| 1-5 | 클래스 홈 재접근 | 로그인 화면 유지, 비밀번호 칸 표시 |

### 2. 로그인 실패 (UI-TC-02-1~4) — 케이스마다 독립 세션
| # | 조작 | 기대 |
|---|---|---|
| 2-1 | 정상 아이디 + 틀린 비밀번호 → 로그인 | "이메일 또는 비밀번호가 일치하지 않습니다", 로그인 화면 유지 |
| 2-2 | 없는 아이디 + 임의 비밀번호 → 로그인 | 2-1과 글자 그대로 같은 문구(계정 존재 여부 미노출), 로그인 화면 유지 |
| 2-3 | 잘못된 이메일 형식 + 7자 이하 비밀번호 입력 | 제출 전에 "잘못된 이메일 형식입니다", "비밀번호는 8자리 이상 입력해주세요" |
| 2-4 | 전체 누락 / 이메일만 누락 / 비밀번호만 누락 → 로그인 | 첫 빈 칸으로 포커스 이동, 필수 입력 검증 상태·안내 존재, 로그인 요청 미전송, 이동 없음 |

2-4의 안내 문구("이 입력란을 작성하세요")는 브라우저 말풍선이라 문구 대신 검증 상태로 판정한다. 2-4의 세 단계는 한 테스트 안의 단계이며, 단계마다 로그인 화면으로 다시 이동해 폼을 초기화한다(로그인이 성공하지 않으므로 넘겨지는 세션 상태가 없다).

### 3. 과목 학습 확인 (UI-TC-03)

| 3-2 | 수업 목록 탭 | "수업 N개", 진도 링 |

### 4. 시험 응시·재응시 (UI-TC-04)
부하 테스트(part2)의 시험 사이클(입장 → 시작 → 제출 → 종료 → 재응시 초기화)과 같은 흐름을 UI로 수행한다.
시작할 때 이전 실행이 남긴 상태를 먼저 응시 전으로 맞춘다(응시 완료면 "테스트 재응시", 시작 뒤 끊겨 응시 중이면 "테스트 이어하기"로 제출·종료까지 마친 뒤 재응시). 끝도 응시 전 상태다.

| # | 조작 | 기대 |
|---|---|---|
| 4-1 | 학습자 로그인 → SANDBOX → 지정 차시 주소(`/courses/731/lectures/1585`)로 이동 → ‘01 TEST’ 영역의 테스트 시작하기 | 응시 전 차시 ID 확인, testroom 온보딩(테스트 안내·유의 사항) |
| 4-2 | 유의사항 체크 전 | "다음" 버튼 비활성 |
| 4-3 | 체크 → 다음 → 테스트 시작 | "모든 응시 준비 완료" → 문항(Untitled Quiz, 보기 Correct/Incorrect) |
| 4-4 | 보기 선택 → 제출 | "제출 완료" |
| 4-5 | 테스트 종료 → 모달 | 확인 체크 전 종료 버튼 비활성 |
| 4-6 | 체크 → 종료 → 다음 | "테스트가 종료되었습니다" → 지정 차시 1585로 복귀, "테스트 응시 완료" |
| 4-7 | 완료 화면 오른쪽 아래 "테스트 재응시" | 재응시 요청(`reset/by_self`) 응답이 HTTP 200이고 본문 `_result.status == ok`, 재응시 전후 지정 차시 URL 확인, 같은 화면이 "테스트 시작하기"로 복귀(응시 전) |

### 6. 교육자 일정 CRUD (UI-TC-06)
실패 후 정리는 목록 로딩 완료와 제목 유무를 확인한다. 제목이 0건이면 건너뛰며, UI 조회 오류·일정 조회 HTTP/네트워크 실패는 숨기지 않고 보고한다. 여러 제목을 정리할 때도 목록 보기 상태를 유지한다.

| # | 조작 | 기대 |
|---|---|---|
| 6-1 | 교육자 로그인 | 사이드바에 구성원·설정 메뉴 |
| 6-2 | 수업 일정 → 만들기 → 제목·날짜 → 저장 | 목록 보기에 일정 표시 |
| 6-3 | 일정 클릭 → 연필 → 제목 수정 → 저장 | 수정된 제목 표시 |
| 6-4 | 새로고침 → 목록 보기 | 수정값 유지 |
| 6-5 | 일정 클릭 → 휴지통 → "이 일정을 삭제하시겠습니까?" 삭제 | 목록에서 제거 |

## 추적성

API TC는 같은 기능 영역의 교차 검증 참고이며 UI TC와 항상 1:1 대응하지 않는다.

| UI TC | 메뉴·역할 Scope | 관련 API TC / 타 파트 |
|---|---|---|
| UI-TC-01 | 클래스 홈 · 학습자 조회, 역할별 메뉴 | TC-CP-01 (팀원 작성 part1 컬렉션, 공개본 미포함) |
| UI-TC-03 | 학습 과목 · 학습자 진입·학습 흐름 | TC-CO-01~03 |
| UI-TC-04 | 시험 입장→응시→제출→재응시 1사이클 | TC-EX-01(시험 과목 조회)·03(체류 기록)·05(자가 재응시 허용)·06(응시 흐름 강제), part2 JMeter 시험 사이클(test/enter → start → response/add → stop → reset/by_self) |
| UI-TC-05 | 게시판 · 학습자 읽기·쓰기·댓글 | TC-BD-01(목록)·02(상세)·03(작성)·08(본인 글 수정)·09(본인 글 삭제). 댓글 API TC는 없음 |
| UI-TC-06 | 수업 일정 · 교육자 생성·수정·삭제, 클래스 홈 · 교육자 관리 메뉴 | TC-SC-03-01/02/03(생성·수정·삭제) |
| UI-TC-07 | 수업 일정 · 교육자→학습자 반영 | TC-SC-01-01(일정 목록)·TC-SC-03-01/03(생성·삭제) |
